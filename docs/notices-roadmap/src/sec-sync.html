9.1 What the sync does today

"Sync All" on the dashboard posts a message to the GST Keeper Chrome extension, which logs in to the portal for each client with saved credentials, asks a human to type one CAPTCHA per client, reads Notices & Orders, then Refunds and DRC-03 for the same session, and writes the results to Supabase. Three properties of this write path shape everything on the dashboard:

  • Delete-then-insert per client (replaceNotices, extension/background.js:102–105): every sync deletes the client's gst_notices rows and inserts what the portal returned. Staff-entered status, priority, owner, reply and order details are lost each time, and pulled_at is reset for every row, so "Last 24 Hours" counts re-pulled rows, not new notices.
  • Failure replaces history (extension/content.js:2471, 2744): a pull that fails writes a single diagnostic row with the description "PULL FAILED: …" in place of all the client's notices. That row is then counted as a notice by every tile and report.
  • Not wired to the production domain (extension/manifest.json:32): the app-side bridge script is injected only on *.vercel.app hosts. On gst.vjdesai.com the page never receives the extension's ready ping, so the dashboard shows "Extension not detected" (as in the screenshot) and Sync All cannot start there at all. Staff must be using the Vercel preview URL to sync. Adding the production host to the manifest is a one-line fix and is in Phase 0.
  • Fragile for a firm-wide run: the extension drops any job older than 20 minutes (content.js:148), failures inside the refunds and DRC-03 steps are not logged, and portal passwords are copied in plain text into chrome.storage.local for every queued client (background.js:410).
  • Manual and browser-bound: the sync exists only when a staff member is in Chrome with the extension enabled; there is no schedule, no retry, no record of how many rows were new, changed or removed, and the Windows agent runner (agent/) has no notices handler yet.

Legal posture stays as documented in agent/README.md

Automated access to the GST portal with stored client credentials is against GSTN's terms and carries IT Act exposure. This roadmap does not add CAPTCHA auto-solving. Unattended runs rely on the agent's existing session reuse (storageState), with a human entering one CAPTCHA per client session when it expires, written client authorisation on file, and the agent machine kept office-local. The partner should confirm this posture before Phase 4 is scheduled.
